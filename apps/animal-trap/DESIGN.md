## 3. 인증·권한

| 역할 | 자격 | 할 수 있는 것 | 뷰 |
|---|---|---|---|
| 관리자 | `ADMIN_PASSWORD`(secret), 매 호출 | 판 만들기, 문제은행 관리 | — |
| 교사 | **교사 열쇠**(128비트 무작위, base32), 판 생성 시 발급, 브라우저 저장 | 진행 전부, 조작권 해제, PIN 잠금 해제·재발급, TV 열쇠 재발급 | `teacherView` |
| TV | **TV 열쇠**(128비트, 읽기 전용) | 보기만. 모든 쓰기 명령 서버 거부 | `tvView` |
| 팀 조작자 | 팀 번호 + PIN(4자리) + **조작권 토큰**(128비트) | 덫 수정·확정, 이동, 답안, 정찰 | `teamView(t)` |
| 팀 관람자 | 팀 번호 + PIN | 보기만 | `teamView(t)`(토큰 없음) |

- **입장(join)**: PIN만으로 인증. 그 팀의 조작권이 비어 있으면 **원자적으로 획득**해 토큰을 발급(판·팀·`controlGen`에 귀속). 이미 있으면 관람자로 입장. 토큰은 조작자 응답에만 담긴다.
- **조작 명령**: PIN + 토큰 + `controlGen` 일치 확인. 교사가 조작권을 해제하면 `controlGen++` → 이전 토큰 즉시 무효, 그 소켓에 '조작권 해제' 통보 후 관람자로 강등.
- **판 코드는 비밀이 아니다.** 권한 판단에 쓰지 않는다. 인증값은 헤더/본문으로만, URL 쿼리 금지.
- **TV 링크**: `/tv#<code>.<tvKey>`(fragment는 서버에 전송되지 않음 — 암호화가 아님). 화면이 읽는 즉시 `history.replaceState`로 주소에서 제거, 교사 화면은 `rel=noopener`로 연다. 열쇠는 로그에 남기지 않는다. 유출 시 교사가 재발급(이전 열쇠 무효).
- **PIN 실패 제한**: '새 입장 시도'에만 적용(팀별 5회 실패 → 30초, DO storage에 영속). 이미 입장한 소켓·토큰 보유자는 영향 없음 → 공격자가 정상 팀을 멈출 수 없음. 교사가 잠금 해제·PIN 재발급 가능.
- 무작위값은 `crypto.getRandomValues`, 비교는 상수 시간.

## 4. 보드·규칙 엔진 (`src/game`, 순수 함수)

### 4-1. 좌표
- 16×16, `(r,c)` 0..15, 셀 id = `r*16+c`.
- 오아시스: `(7,7) (7,8) (8,7) (8,8)`.
- 출발 구역 좌상단: NW`(0,0)` N`(0,7)` NE`(0,14)` W`(7,0)` E`(7,14)` SW`(14,0)` S`(14,7)` SE`(14,14)`, 각 2×2. 추첨으로 팀에 무작위 배정.
- 팀 출발 칸: 구역 2×2 중 **오아시스에 가장 가까운 칸**(결정적).

### 4-2. 덫
- 팀당 일반 10 + 귀환 1 + 속박 1 + 혼란 1 = 13.
- 설치 가능: 오아시스 제외, **자기 출발 구역 제외**, 한 팀은 한 칸에 1개. 다른 팀과 중첩 허용.
- 자동 배치: 가능한 칸에서 균등 무작위 13칸 + 종류 무작위(서버 RNG, 시드는 서버에만 저장·어떤 뷰에도 미포함).
- 설치 수정: 내 덫 하나를 가능한 칸으로 옮기기 / 내 덫 두 개의 위치 교환. 확정 후 불가. 각 수정은 즉시 영속.

### 4-3. 라운드 처리 (R = 현재 라운드 번호, 순서 고정)

**상태이상 표현:** `bindRounds`, `confuseRounds` = 효과가 적용되는 **라운드 번호 집합**. 라운드 R에 받은 효과는 `{R+1, R+2}`. 재적용 시 합집합 대신 `{R'+1, R'+2}`와 기존 미래 라운드의 합집합에서 **최대 2개**(= max(기존 남은, 2)). 차감 연산 없음 → 중복 차감·취소 라운드 차감이 구조적으로 불가.

```
[MOVE_OPEN]   조작자가 8방향 중 1칸 제출(보드 밖 거부). 속박 라운드(R ∈ bindRounds) 팀은 제출 불가.
[LANDED]      (이동 마감 또는 전원 제출) 
   1 이동 확정: 미제출·속박 팀 = 제자리(이번 라운드 착지 없음)
   2 착지 스냅샷: 실제로 이동한 팀의 도착 칸별 활성 덫 id 집합 고정 (같은 칸 동시 착지 = 같은 n)
   3 착지 분류(임시, 아직 확정 아님):
     - 모든 실제 착지는 그 팀 방문 이력에 기록(임시)
     - 오아시스 칸: 팀 최초 방문이면 '이번 라운드 오아시스 신규 도착' 후보
     - 상대 출발 구역 칸: 그 상대 구역 최초 방문이면 +10 후보
     - 일반 칸 n=0: 팀 최초 방문이면 +1 후보 (지역 보상 칸·출발 초기 칸 제외)
     - n≥1: 난이도(n=1 쉬움 / n=2 보통 / n≥3 어려움, 1-1 확정) 문항 배정(임시)
[QUESTION_OPEN] 문항 배정 팀이 있을 때만. 조작자는 1회 답안(첫 답안 불변 저장 후 정오만 응답).
                마감 시 미응답 = 오답. 배정 팀이 없으면 이 단계 생략.
[RESOLVE]     (한 번만, round.settled로 보장)
   4 점수 후보: 정답 +(n+2), 오답 -(n+1)
   5 덫 제거: 한 팀이라도 정답인 칸의 스냅샷 덫 집합 제거
   6 특수 효과(오답 팀만): 스냅샷의 특수 덫 중 가장 강한 1개 — 귀환 > 속박 > 혼란
       귀환: 자기 출발 칸으로 이동(그 칸에서 판정·보상·방문 기록 없음)
       속박: bindRounds ← {R+1,R+2} / 혼란: confuseRounds ← {R+1,R+2}
   7 오아시스: 이번 라운드 신규 도착 팀 전원 공동 순위 = 1 + (이전 라운드까지 도착 팀 수)
       → 1위 30 / 2위 20 / 3위 이후 15, 정찰권 1회 부여
   8 확정: 임시 결과(위치·방문·점수·보상·상태이상·정찰권·덫 제거)를 확정 상태에 한 번에 반영, 이벤트 기록
[ROUND_SUMMARY] 결과 표시. 교사 '다음 라운드'(또는 D17 자동). 메인 타이머가 끝났으면 FINISHED.
```

- **확정 상태(`committed`)와 진행 라운드(`pending`)를 분리**한다. LANDED~RESOLVE 동안의 모든 변경은 `pending`에만. RESOLVE 8단계에서 `committed`에 병합. D5(수동 종료)·D13(만료 폐기)은 `pending`을 버리기만 하면 된다.
- 같은 칸 재방문: 덫이 남아 있으면 그 시점 n으로 새 문항. 제자리 연속 풀이 없음.
- **표시 위치**: 이동은 공개 정보이므로 `LANDED`부터 모든 뷰가 **이번 라운드 착지 위치(pending)**를 보여준다(TV 이동 연출과 일치). RESOLVE에서 귀환이 나오면 그 위치로 갱신. 수동 종료로 폐기되면 확정 위치로 되돌아간다.
- **센서**: 서버가 **그 팀의 현재 표시 위치**(위 규칙)에서만 계산 — 현재 칸 제외 주변 8칸의 모든 활성 덫 개수. 착지 후 RESOLVE 전에는 스냅샷 시점의 활성 덫 기준, RESOLVE 후에는 제거 반영 후 기준. 임의 좌표 조회·이동 미리보기 API 없음. 혼란 라운드면 `null`.
- **정찰**: 정찰권은 RESOLVE 8단계에서 확정 상태로 부여된다. 정찰권이 있는 팀은 `ROUND_SUMMARY`·`MOVE_OPEN`·**`FINISHED`**에서(일시정지 중 불가) 3×3 좌상단 좌표를 제출 → 서버가 그 시점 `committed` 기준으로 영역 내 **상대 덫이 있는 칸과 칸별 개수**를 계산해 그 팀 확정 상태에 저장, 정찰권 소멸(원자적, 즉시 확정 — D5 롤백 대상 아님). 마지막 라운드에 도착한 팀도 종료 화면에서 1회 사용 가능(점수 영향 없음). 미리보기는 화면에서 사각형만 그림(서버 조회 없음). 이후 그 칸의 덫이 제거되면 '제거됨' 표시.
- 최종 순위: 점수 내림차순, 같은 점수 같은 순위, 다음 순위 건너뜀(1,1,3). 공동 우승 허용.

## 5. 판 상태 머신 (DO)

### 5-1. 단계
```
LOBBY ─추첨→ DRAWN ─설치 시작→ TRAP_SETUP ─(전원 확정 or 마감)→ READY ─게임 시작→ RUNNING ─→ FINISHED ─→ REVIEW
RUNNING 라운드: MOVE_OPEN → LANDED → [QUESTION_OPEN] → RESOLVE → ROUND_SUMMARY → (다음 라운드)
```

### 5-2. 명령 처리와 저장 (중복 방지)
- 모든 명령(HTTP·소켓·alarm)은 DO 안 `handle(cmd)` 한 곳에서: ① 권한 확인 ② **같은 행위자의 같은 `requestId`가 이미 처리됐으면 저장된 결과를 그대로 반환**(단계가 바뀐 뒤의 재전송도 성공) ③ `tick(now)` — 지난 마감 적용 ④ 상태·라운드·단계 확인 ⑤ 적용 ⑥ **저장 성공 후** 응답·푸시.
- 멱등: 명령마다 `requestId`. 행위자별 최근 처리키를 상태와 **같은 저장 단위**로 영속 → 재전송은 같은 결과 반환. 답안은 문항별 첫 답안 불변. RESOLVE는 `round.settled`가 참이면 무시.
- 저장: `storage.put({state, events:<seq>…})` 다중 키 원자 저장. 키 분리 — `state`(확정+진행 라운드), `bank`(판 생성 시 고정한 문항, 1회 저장), `events:<seq>`(감사 로그). 값당 크기 제한 회피.
- 모든 뷰에 단조 증가 `stateVersion`. 화면은 더 낮은 버전의 응답·푸시를 버린다.

### 5-3. 시계
- 저장 값: `durationMs`, `activeElapsedMs`, `runningSince`(일시정지면 null), 단계는 `phaseEndsAt`(진행 중) 또는 `phaseRemainingMs`(일시정지 중).
- 메인 남은 시간 = `durationMs − (activeElapsedMs + (now − runningSince))`. 일시정지 시 `activeElapsedMs`에 누적하고 `runningSince=null`, 단계 마감을 잔여시간으로 변환. 재개 시 역변환.
- 뷰는 `serverNow`, `paused`, `mainRemainingMs`, `phaseRemainingMs`를 보내고 화면은 수신 시각 기준으로 줄여 표시(일시정지면 고정).
- 메인 타이머는 RUNNING의 모든 라운드 단계에서 흐른다(문제 풀이 중에도, 기획서 9.2). 설치·로비는 메인 타이머 밖.

### 5-4. alarm
- alarm은 1개. 예약 시각 = **유효한 마감들의 최솟값**: 현재 단계 마감, (아직 만료 전이면) 메인 만료. 일시정지 중에는 예약하지 않음.
- 메인 만료 처리 후 `finishAfterRound=true`를 저장하고 메인 만료는 더 이상 후보에서 제외(즉시 재발화 반복 방지).
- alarm 핸들러는 `tick(now)`만 호출(재실행돼도 이미 적용된 마감은 무시 = 멱등). 처리 후 다음 alarm 재계산.
- 같은 시각 우선순위: 메인 만료 → 단계 마감 (D13).

### 5-5. 재접속·hibernation
- 생성자에서 `blockConcurrencyWhile`로 storage 복원 완료 후 처리.
- **자격 세대**를 영속: `tvGen`(TV 열쇠 재발급마다 +1), 팀별 `pinGen`(PIN 재발급마다 +1), 팀별 `controlGen`. 소켓 attachment에 `{role, team, tvGen|pinGen, controlGen}` 저장.
- 재발급·조작권 해제 시 해당 소켓에 통보 후 닫거나(TV·PIN) 관람자로 강등(조작권). hibernation에서 깨어날 때와 매 메시지 처리 때도 attachment 세대를 현재 값과 비교해 다르면 같은 처리.
- 접속·재접속 시 전체 뷰 1회 전송, 이후 변경 시 푸시.

### 5-6. 판 생성 검증
- 선택한 세트에 **쉬움·보통·어려움 각 1문항 이상** 없으면 생성 거부. 각 12문항 미만이면 경고(15분 판 기준 팀 내 중복 가능).
- 문항 고정 스냅샷 최대 300문항(넘으면 거부).
- D1 판 목록 등록과 DO 생성은 'DO 먼저 생성 → D1 등록', 실패 시 같은 코드로 재시도 가능(코드 충돌은 재생성).

## 6. 화면별 뷰와 비밀

### 6-1. 비밀 정책
1. **원본 숨은 정보는 허용된 관찰자 외에는 전송하지 않는다**: 덫 id·셀·종류·소유자, 배치 시드, 정답 키, 문항 내용·난이도·배정 id, 센서, 정찰 영역·결과, PIN·열쇠·토큰.
   **명시적 예외(이것만 허용):** 자기 팀 덫 → 그 팀 / 자기 정찰 결과(상대 덫 칸·개수) → 그 팀 / 자기 센서 값 → 그 팀 / 자기 문항 → 그 팀 / 자기 답 제출 후 그 문항의 정오 → 그 팀 / 조작권 토큰 → 그 팀 조작자 응답에만 / **종료 후(FINISHED·REVIEW) 전체 덫 위치와 사용된 모든 문항의 정답·해설 → 교사**(공개 전 미리보기용) / 종료 후 교사가 공개한 덫 지도 → 모두 / 복습에서 교사가 공개한 문항의 정답·해설 → 모두(TV·팀 포함) / PIN 목록·TV 열쇠 → 교사.
2. **공개 관측값에서 가능한 추론은 허용**(D12): 위치·이동, 팀별 '문제 풀이 중' 여부, 정답/오답, 점수 변동, 귀환·속박·혼란 발생, 오아시스 도착. TV에 보이는 정보이므로 팀 뷰에서 숨겨도 의미가 없다.
3. 뷰는 **허용 필드만 조립**(삭제 방식 금지). HTTP·소켓·이벤트·오류 메시지 모두 같은 원칙.

## 9. 운영 한도 (Cloudflare 무료 플랜, 계정 전체 합산 — 애니멀 더비 포함)

- 한도 초과는 과금이 아니라 **오류**이므로: 한도 오류를 화면에 명확히 표시, 판 보존 정리 cron(정산 30일·미정산 90일, 애니멀 더비와 같은 정책), 첫 수업 후 대시보드 사용량 확인. 수업이 늘면 Workers Paid($5/월) 검토.
