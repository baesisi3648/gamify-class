# 애니멀 트랩: 오아시스 쟁탈전 — 게임 기획·개발 계획서

> **버전:** v2.0 (2026-11-08)  
> **목적:** Claude / Claude Code에 전달해 기존 `gamify_class` 사이트의 `apps > 수업`에 별도 게임을 구현하기 위한 통합 요구사항  
> **원칙:** **[확정]** 사용자가 채택한 규칙, **[구현 기본안]** 충돌 방지와 개발 일관성을 위한 세부 운영 해석, **[추후 결정]** 아직 별도 승인이 없는 사항으로 표시한다.  
> **변경 요약:** 16×16 확정, 일반·특수 덫 통합 개수로 퀴즈·점수 계산, 안전 칸 최초 방문 +3점, 오아시스 공동 도착 순위, 40점 조기 종료 **폐기**, 교사 설정 타이머·수동 종료·최종 점수 우승으로 변경.

---

## 0. Claude에게 주는 최우선 지시

1. 먼저 실제 `gamify_class` 프로젝트의 파일 구조, `apps > 수업` 메뉴, 라우트, DB, 인증, 실시간 통신, 배포 환경, 기존 **애니멀 더비**의 운영 흐름을 조사한다.
2. 애니멀 더비는 **TV 송출/학생 QR 접속/교사 진행 UI를 참고하는 사례**일 뿐, 애니멀 트랩은 **별도 라우트·게임 세션·상태·문제은행·데이터 저장 공간**을 갖는다. 기존 게임을 훼손하거나 데이터를 섞지 않는다.
3. 프로젝트의 기존 프레임워크·스타일·서버 구조를 우선 재사용하며, 불필요한 신규 의존성이나 서비스 도입을 피한다.
4. 구현 전 현재 코드베이스에 맞는 파일 변경 계획·핵심 데이터 모델·실시간 권한 모델을 짧게 보고하고, 그다음 구현한다.
5. 덫, 문항 정답, 점수, 시간, 라운드 상태는 서버가 권위 있게 관리한다. 학생 클라이언트에는 **허가된 정보만** 내려주며, 타 팀 덫을 전송한 뒤 CSS로 숨기는 구현은 금지한다.
6. 확정 요구사항은 변경하지 않는다. 미정 사항은 문서의 구현 기본안을 사용하되 사용자에게 임의로 확정되었다고 주장하지 않고 목록으로 보고한다.
7. 기능 구현, 자동 테스트, 교사용 실제 사용 흐름, TV·모바일 반응형 UI, 게임 종료 후 **전체 문제 복습 모드**까지 제공한다.
8. 이 문서는 구현 가능한 사양서이지만 실제 코드베이스를 보지 못한 상태에서 작성한 것이므로 구체 라이브러리와 DB 명칭은 가정하지 않는다.

## 1. 게임 개요

- **[구현 기본안] 정식 이름:** 애니멀 트랩: 오아시스 쟁탈전 / 메뉴명: **애니멀 트랩**.
- **[확정] 형식:** 교사가 TV·빔으로 실시간 공용 보드를 송출하고, 8팀 학생이 각자 또는 팀 단위로 QR코드에 접속하여 이동을 선택하고 객관식 문제를 푼다.
- **[확정] 목표:** 정해진 제한 시간 동안 덫을 극복해 점수를 쌓고 오아시스·상대 팀 시작 지점의 보너스를 획득한다. 종료 시 최고 점수 팀이 우승한다.
- **학습 목표:** 교과 개념 복습, 위험·보상 판단, 모둠 토의와 협력, 종료 후 오답·오개념 분석.
- **시각 콘셉트:** 초록 초원·정글·수련의 숲 느낌의 밝은 판타지 자연환경. 8마리 동물, 반짝이는 위치 표식, 잔상 이동, 덫 이펙트, 오아시스 보상 연출.
- **배경 음악:** 애니멀 더비와 같은 **'수련의 숲'** 음악 사용을 희망. 실제 프로젝트에 해당 곡의 사용 가능한 음원 및 라이선스가 있는지 확인하고 재사용 가능할 때만 적용. 자동재생 제한에 대비한 사용자 클릭 후 재생·음소거·볼륨 제공.

## 2. 역할과 화면

| 역할 | 기능 | 비공개 데이터 접근 |
|---|---|---|
| 교사 설정/관리 | 게임 만들기, 문제 업로드/선택, 제한시간 설정, 팀 관리, 출발점 추첨, 덫 설치 단계 관리, 타이머·라운드 제어, 수동 종료, 문제 복습 | 관리에 필요한 전체 상태, 단 학생 화면에 노출 금지 |
| 공용 TV 화면 | 전체 보드, 동물 위치·이동 잔상, 라운드·타이머·팀별 진행 상태·점수, 이벤트, 최종 결과 | 게임 중 숨겨진 덫 지도는 표시하지 않음 |
| 팀 모바일 화면 | 자기 동물·지도 확대, 자신의 반짝이는 덫, 주변 8칸 덫 합계, 이동 확정, 퀴즈, 점수, 오아시스 정찰 | 자기 덫 및 정찰로 공개된 타 팀 덫만 |

학생 인증·팀 입장 방식은 기존 프로젝트의 안전한 QR 세션 패턴을 재사용하되, 팀별 접근 토큰을 검증한다. 하나의 팀에 여러 기기가 접속 가능한 경우 **[구현 기본안]** 한 기기를 조작 담당으로 설정하거나 팀 조작 권한을 서버에서 단일화해 중복 답안·이동 제출을 막는다.

## 3. 보드 규격과 이동

### 3.1 공간

- **[확정] 16×16 = 256칸**. 내부 좌표는 `(row, col)`이며 각 값은 `0..15`.
- **[확정] 중앙 2×2 오아시스**, **[구현 기본안]** `(7,7),(7,8),(8,7),(8,8)`.
- **[확정] 2×2 출발 구역 8곳:** 네 모서리 및 동·서·남·북 변 중앙.
- **[구현 기본안] 출발 구역 좌상단 좌표:** NW `(0,0)`, N `(0,7)`, NE `(0,14)`, W `(7,0)`, E `(7,14)`, SW `(14,0)`, S `(14,7)`, SE `(14,14)`.
- **[확정]** 게임 시작 전 8팀에 출발 구역을 중복 없이 무작위 배정한다. 추첨 결과는 TV에 공개할 수 있다.
- **[구현 기본안]** 구역 내 실제 출발 칸은 팀별 서버 지정 1칸으로 기록한다. 보상 판정은 구역의 2×2 어느 칸이든 진입 시 적용한다.
- **[확정]** 매 라운드 상하좌우·대각선 총 8방향 중 정확히 1칸 이동. 보드 외부로 이동 불가.
- **[구현 기본안]** 여러 동물이 같은 칸에 들어가는 것은 허용하고, 겹칠 때 TV에서 아이콘을 겹치지 않게 배열한다. 오아시스도 동시 입장 가능.
- **[구현 기본안]** 정지 행동은 평소 선택 불가; 속박 등 상태이상·교사 특수 운영에 의한 정지만 허용.

### 3.2 덫 설치 금지 지역

- **[확정]** 중앙 2×2 오아시스에는 어떤 덫도 설치 불가.
- **[구현 기본안]** 자신의 시작 구역 2×2에는 덫 설치 불가. 다른 팀 시작 구역에는 덫 설치 가능하되 출발과 동시에 발동하지 않고 **이후 이동해 진입할 때만** 판정.
- 모든 셀에서 덫 배치 및 보상 영역 여부를 서버에서 검증한다.

## 4. 덫 배치·소유권·공개 범위

- **[확정] 팀당 총 13개:** 일반 덫 10개, 특수 덫 3개(귀환·속박·혼란 각 1개).
- **[확정] 서로 다른 팀이 동일 칸에 설치 가능:** 같은 칸의 덫은 팀과 종류에 상관없이 **개체 수 단위**로 계산.
- **[확정] 자신의 덫도 자신에게 발동**하며, 자기 모바일 지도에는 종류·위치가 반짝이는 아이콘으로 보인다.
- **[확정]** 다른 팀의 덫은 기본 비공개. 오아시스에서 획득한 정찰 정보만 해당 팀에 공개한다.
- **[구현 기본안]** 한 팀이 한 칸에 자기 덫을 둘 이상 놓지 못한다. 다른 팀과의 중첩은 허용한다.
- **[구현 기본안]** 각 팀은 설치 단계에서 미리보기·수정·확정을 할 수 있고, 확정 후에는 변경할 수 없다. 교사는 팀별 설치 완료 여부와 개수 확인 가능.
- **[확정]** 덫은 **정답이면 그 칸의 덫 전부 제거**, **오답이면 그 칸의 덫 전부 유지**한다. 일반 덫과 특수 덫 모두 해당.
- **[확정]** 같은 칸 재방문 시, 아직 덫이 남아 있다면 다시 **동일 난이도 기준의 새로운 무작위 문항**으로 도전할 수 있다. 첫 도전과 동일 문항 반복을 최대한 피한다.
- **[구현 기본안]** 떠나지 않고 제자리에서 연속 문제 풀기는 불가. 반드시 다른 칸으로 이동한 뒤 재진입해야 한다.

## 5. 난이도·점수·정답 처리 — 최종 확정

### 5.1 핵심 공식

착지한 칸에 존재하는 **자기 덫 + 상대 덫 + 일반 덫 + 특수 덫**을 전부 더한 개체 수를 `n`이라 한다. 특수 덫도 문제 난이도, 점수, 주변 센서 개수에 **반드시 포함**한다.

| 해당 칸 덫 개수 `n` | 문제 난이도 | 정답 | 오답 |
|---:|---|---:|---:|
| **0** | 출제 없음 | **+3 (팀별 해당 칸 최초 방문 시)** | 해당 없음 |
| 1 | 쉬움 | +3 | -2 |
| 2 | 쉬움 | +4 | -3 |
| 3 | 중간 | +5 | -4 |
| 4 | 중간 | +6 | -5 |
| 5 | 어려움 | +7 | -6 |
| 6 이상 | 어려움 | `+(n+2)` | `-(n+1)` |

- **[확정] n=0:** 문제를 풀지 않고 **안전 탐험 보너스 +3점**. 단 **각 팀은 동일 칸에서 최초 방문 1회만** 보너스를 얻는다. 나중에 다시 방문해도 +3 반복 지급 금지.
- **[구현 기본안]** 덫이 있었던 칸이 정답으로 안전해진 후 다른 라운드에 다시 방문한 팀은, 그 팀의 **해당 칸 최초 방문 여부**로 +3 자격을 판정한다(정답으로 덫을 제거했던 팀은 이미 방문했으므로 재방문 +3 없음).
- **[확정] n>=1:** 해당 난이도의 객관식 문제 1개 출제. 정답은 `n+2`점, 오답은 `-(n+1)`점.
- **[확정] 정답 시 그 칸의 일반·특수 덫을 모두 제거.** 오답 시 하나도 제거하지 않음. 오답이고 특수 덫이 있다면 해당 특수 효과를 추가 적용한다.
- **[구현 기본안]** 점수는 음수 허용. 점수 표시·랭킹·기록 모두 음수를 처리.
- **[구현 기본안]** 칸의 덫이 0개여도 첫 오아시스/다른 팀 출발지 보상은 별도 규칙으로 중첩 지급할 수 있다. 단 일반 안전 보너스는 게임 시작 시 자신이 놓인 초기 칸에는 지급하지 않고, **실제로 이동해 착지**했을 때만 적용한다.
- **[확정]** 문제는 문제은행에서 난이도별 랜덤 출제. 동일 난이도에서도 같은 팀에 이미 출제한 문항은 우선 제외하여 중복 최소화.

### 5.2 정답·오답·재방문 예시

- 일반 덫 2개 + 특수 덫 2개가 있는 칸: **n=4**, 중간 문제. 정답이면 **+6점·4개 모두 제거**, 오답이면 **-5점·4개 유지·해당 특수 효과 발동**.
- 특수 덫 1개만 있는 칸: **n=1**, 쉬움 문제. 정답이면 **+3점·특수 덫 제거**, 오답이면 **-2점·특수 덫 유지·효과 발동**.
- 덫 0개인 새로운 일반 칸: +3점. 같은 팀이 다시 방문하면 0점.
- 오답으로 덫이 남아 있는 칸에 다시 진입: **해당 시점 실제 덫 수**로 난이도를 정하고 이전과 다른 문제를 우선 출제.

### 5.3 동시 착지·덫 제거 경쟁

- **[구현 기본안 / 필수 공정성]** 여러 팀이 한 라운드에 동일 칸에 동시에 도착하면 이동 완료 시점의 덫 집합을 **스냅샷**으로 고정한다. 각 팀은 동일한 n으로 별도 문항을 풀고 점수 획득·감점을 계산한다.
- 한 명 이상이 정답을 맞혔다면 **라운드 채점 확정 때** 해당 칸 덫 집합을 한 번만 제거한다. 정답 제출 순서가 다른 팀 난이도를 변경하지 않게 한다.
- 오답 팀의 특수 덫 효과는 해당 착지 스냅샷 기준으로 적용한다. 로그에는 각 팀의 개별 판정과 공동 제거 사실을 남긴다.

## 6. 특수 덫 (각 팀 3종, 각 1개)

| 종류 | 시각 효과 | 문제 오답 시 효과 |
|---|---|---|
| **귀환 덫** | 소용돌이·포털 | 자기 최초 시작 칸으로 강제 이동 |
| **속박 덫** | 밧줄·모래시계 | **다음 2개 라운드** 이동 불가 |
| **혼란 덫** | 안개·눈가림 | **다음 2개 라운드** 주변 8칸의 덫 개수 감춤 |

- **[확정 채택]** 특수 효과는 **그 칸의 문제를 틀렸을 때만** 발동. 정답이면 점수만 받고 일반·특수 덫 모두 제거.
- **[확정]** 오답이어도 특수 덫은 유지되므로 이후 재방문 시 다시 발동할 수 있음.
- **[구현 기본안]** 한 칸에 복수 특수 덫이 함께 존재하고 오답일 때는 가장 강한 효과 **1개만** 적용. 우선순위: **귀환 > 속박 > 혼란**. 이는 향후 교사가 설정 가능하도록 분리해도 무방.
- **[구현 기본안]** 귀환된 최초 시작 칸에서는 즉시 재귀적으로 덫·보너스를 판정하지 않음. 다음 정상 이동 후 새 칸에서 판정.
- **[구현 기본안]** 속박 기간에는 자동 제자리 유지로 처리하고 새 착지·문제·보너스 없음. 속박 라운드 카운트는 서버가 정확히 두 번 차감.
- **[구현 기본안]** 혼란 상태여도 자신의 덫 표식, 이미 정찰로 획득한 정보, 이동 기능은 유지되며 **주변 덫 개수 수치만 숨김**.
- **[구현 기본안]** 같은 효과를 다시 밟으면 남은 기간은 `max(기존 남은 턴, 2)`로 갱신하고 무한 누적을 방지.

## 7. 주변 덫 탐지·자기 덫 표시

- **[확정]** 이동 후 자기 동물 현재 위치를 제외한 **주변 8칸**(상·하·좌·우·4대각선)의 모든 팀의 일반·특수 덫 개체 수 **총합**을 모바일에 표시한다.
- **[확정]** 한 칸에 여러 팀의 덫이 있으면 덫 개체를 각각 1개로 센다. 보드 밖은 제외.
- **[확정]** 자기 팀이 설치한 아직 활성화된 덫은 모바일에서 반짝이는 표식으로 표시하고, 제거 시 즉시 사라진다.
- **[확정]** 혼란 효과 중에는 주변 덫 총개수 표시를 숨기되, 공개 권한이 있는 자기 덫과 정찰로 획득한 상대 덫 위치는 계속 보여준다.
- **[구현 기본안]** 모바일 지도는 탭에서 확대·축소·이동 가능하며 방향 선택 전 도착 예상 칸을 강조. 다른 팀 덫의 비공개 좌표가 개발자 도구·응답 페이로드에 포함되지 않도록 한다.

## 8. 오아시스와 출발 구역 보상

### 8.1 오아시스 진입 보상

- **[확정]** 중앙 2×2에 처음 들어온 팀에 **팀당 1회만** 오아시스 점수를 지급. 오아시스에 여러 동물이 동시에/같은 칸에 진입 가능.
- **[확정] 도착 순위별 보상:** 최초 1번째 **+20점**, 최초 2번째 **+30점**, 3번째 이후 **+15점**.
- **[확정] 공동 도착:** 같은 라운드에서 처음 진입한 팀은 **공동 순위**, **동일 점수**. 다음 순위는 도착 팀 **실제 수만큼 건너뛰는 경쟁 순위 방식** 적용.

| 라운드 | 처음 진입한 팀 | 순위 및 각 팀 점수 | 이후 다음 도착 순위 |
|---|---|---|---|
| 7 | A·C | 공동 1위, 각 +20 | 3번째 |
| 8 | B | 3위, +15 | 4번째 |
| 별도 예시: 7 | A | 1위, +20 | 2번째 |
| 별도 예시: 8 | B·C | 공동 2위, 각 +30 | 4번째 |

- **[구현 기본안]** 어떤 팀이 이전 라운드에 이미 오아시스에 있었어도 **이번 라운드 최초 방문한 팀만** 공동 도착 계산에 포함한다.
- **[확정]** 이미 방문한 팀의 재진입에는 추가 오아시스 점수 없음.
- **[구현 기본안]** 오아시스는 항상 덫 0개이지만, **오아시스 보상과 일반 안전 탐험 +3의 중복 지급을 막기 위해** 오아시스 칸에서는 `+3 안전 보너스`를 적용하지 않는다. 보상 타일은 고유 보상만 지급. 이 예외는 다른 팀 시작 구역에도 동일 적용하는 것을 기본안으로 한다.

### 8.2 오아시스 3×3 정찰

- **[확정]** 오아시스를 최초 방문한 팀은 지도에서 원하는 **연속 3×3 영역 한 곳**을 선택해 그곳의 **상대 팀 덫 위치**를 본다.
- **[확정]** 정찰 결과는 그 팀에게만 공개되며 게임 종료까지 지속. 자기 덫은 원래 보이므로 함께 구분 표시.
- **[구현 기본안]** 3×3 영역은 보드 경계 안에 완전히 들어와야 한다. 확정 전 영역 미리보기 가능, 확정하면 되돌릴 수 없음.
- **[구현 기본안]** 같은 팀의 정찰 사용은 최초 오아시스 방문 보상에 묶어 **1회만** 허용.
- **[구현 기본안]** 정찰은 사용 시점의 **활성 덫 위치에 관한 정보**를 제공하는 것으로 해석한다. 공개되었던 덫이 정답으로 제거되면 지도에서 ‘제거됨’ 또는 흐린 표시로 갱신하여 현재 덫과 혼동하지 않게 한다.
- **[구현 기본안]** 상대 팀 정찰 정보는 개인/팀 권한으로 필터링하여 전송한다. 게임 종료 후 교사 선택에 따라 전체 덫 공개.

### 8.3 상대 팀 출발 지역

- **[확정]** 자기 출발 구역을 제외한 다른 팀 **2×2 시작 구역**에 도착하면 +10점.
- **[구현 기본안 / 기존 추천 수용]** **상대 팀별 출발 구역마다 최초 1회만** 지급. 동일 상대의 2×2칸 내에서 이동하거나 재방문해도 중복 지급 안 함.
- **[구현 기본안]** 처음 방문한 상대 시작 구역에서 +10점을 받고, 그 칸의 덫 판정도 별도 수행. 안전 보너스 +3은 특수 보상 구역에서는 제외(8.1 참고).

## 9. 타이머 기반 종료 — 40점 종료 규칙 폐기

### 9.1 시작 전 설정

- **[확정]** 교사가 게임 시작 전 **제한시간을 직접 설정**한다.
- **[구현 기본안]** 기본값 **15분**, 분 단위 조절(예: 1~60분), 설정 화면에서 시작 전 수정 가능.
- **[확정]** 게임 중 TV와 교사 화면에 남은 시간을 크게 표시한다.
- **[확정 채택]** 교사는 **일시정지 / 재개**를 할 수 있다. 일시정지 중 서버 타이머가 흐르지 않도록 한다.
- **[확정]** 제한시간이 지나면 자동 종료되며, 교사는 언제든 **수동 게임 종료** 버튼을 누를 수 있다.
- **[중요] 기존 '40점 먼저 달성 시 종료' 규칙은 삭제**한다. 어떤 팀이 40점·50점·그 이상을 얻어도 제한시간 또는 교사 종료 전까지 게임은 계속된다.

### 9.2 종료 시 진행 중 퀴즈 처리 — 채택한 추천안

- **[확정 채택] 타이머 만료:** 새 이동/새 라운드 시작 금지. **이미 시작된 라운드에서 출제된 문제는 제출/제한시간 처리까지 마무리한 후** 결과를 확정하고 자동 종료. 이때 메인 타이머는 00:00을 표시하며 ‘마지막 문제 정산 중’ 상태를 별도 표시한다.
- **[확정 채택] 교사의 수동 강제 종료:** 즉시 새 입력을 차단하고 종료. **이미 서버가 확정한 점수와 보상만** 집계하며, 미제출 문항은 미응답/취소 기록으로 남기고 새 감점은 부과하지 않는 것을 기본안으로 한다.
- **[구현 기본안]** 시간 만료 직전 이동 확정만 되고 문제 출제가 아직 끝나지 않은 경우, 서버가 해당 라운드를 이미 `MOVES_LOCKED` 이상으로 전환했다면 라운드 처리를 완료. 아직 모든 이동을 잠그지 않았다면 그 미완료 라운드는 취소하고 직전 점수로 마감. 경계는 서버 타임스탬프·상태 전이 기준으로 고정한다.
- **[구현 기본안]** 라운드별 문제 풀이 제한시간(예: 30~90초)을 별도 교사 설정으로 둬서 시간 만료 후 무기한 대기하지 않도록 한다. 제한시간 만료 시 미응답 처리는 **오답으로 처리**하는 것이 기존 제안의 기본안이며, 게임 종료 과정에서는 서버가 정한 일관된 처리 정책을 적용.
- **[구현 기본안]** 수동 종료는 확인 팝업(‘진행 중인 문제는 취소되며 현재 점수로 종료합니다’)을 거친다. 교사는 수동 종료와 일시정지를 혼동하지 않아야 한다.
- **[구현 기본안]** 새 라운드를 교사가 버튼으로 시작하도록 하고, 문제 풀이 중에도 본 타이머는 계속 진행(일시정지 시에만 멈춤).

### 9.3 최종 순위

- **[확정]** 종료 시 서버가 모든 팀의 누적 점수를 기준으로 순위를 계산하며 **가장 점수가 높은 팀이 우승**.
- **[확정 채택] 동점이면 공동 순위**, 공동 1위면 공동 우승. 점수가 같은데 오아시스 도착 순서나 정답 수로 강제로 순위를 나누지 않는다.
- **[구현 기본안]** 정렬: 점수 내림차순. 점수가 같으면 같은 등수, 그다음 등수는 동점 팀 수만큼 건너뛰는 경쟁 순위(`1,1,3...`) 사용. UI 목록 표시 순서는 팀명순으로 안정화 가능하되 순위는 같게 유지.
- **[확정]** 종료 화면에서 결과와 함께 전체 퀴즈 복습·해설 진행 모드로 전환 가능.

## 10. 문제은행 및 문제 풀이

- **[확정]** 객관식 문제 세트는 `쉬움 / 중간 / 어려움` 세 단계로 구성, 기존 애니멀 더비 문제관리 UX를 참고하되 저장 데이터는 분리.
- **[구현 기본안]** 필드: 문제 ID, 문제 세트 ID, 난이도, 질문, 선택지 배열, 정답 선택지 ID, 해설(선택), 이미지(선택), 단원·태그(선택), 활성화 여부.
- **[구현 기본안]** 교사는 문제 세트를 선택·작성·수정·삭제·미리보기·JSON 내보내기/가져오기 할 수 있도록 한다. 실제 JSON 스키마는 기존 프로젝트의 것과 호환 여부를 확인하고, 새 게임 고유 버전 필드로 데이터 혼합 방지.
- **[확정]** 도착 칸 n에 따라 난이도 확정 후 해당 난이도 문제은행에서 랜덤 출제. 같은 팀에는 이미 나온 문제를 우선 제외; 필요할 때만 재사용.
- **[구현 기본안]** 서버에서 팀·세션별 출제 이력을 유지. 문항 중복을 더 줄이기 위해 방 전체 출제 이력도 보조 활용하되, 난이도별 문제 수가 부족할 때 게임이 멈추지 않는 순환 정책 제공.
- **[구현 기본안]** 답안은 1회만 제출·수정 불가, 서버 채점, 타임아웃 처리와 접속 끊김 후 재접속 지원.
- **[구현 기본안]** 각 팀은 문제 풀이 중 문제 텍스트와 선택지만 수신. 정답·해설은 서버에 보관하고 해당 문제를 제출하거나 종료한 뒤에만 적절한 시점에 노출.
- **[구현 기본안]** 이미 사용한 문항 기록, 팀별 정오답, 난이도, 획득/감점, 적용된 덫 수를 이벤트로 저장해 종료 후 교사가 복습에 사용.

## 11. 게임 세션 및 라운드 상태 머신

### 11.1 세션 라이프사이클

`DRAFT → LOBBY → START_DRAW → TRAP_SETUP → READY → RUNNING → TIME_EXPIRED_SETTLING → FINISHED → REVIEW`

- **DRAFT/LOBBY:** 교사 문제·시간·팀 설정, QR 입장.
- **START_DRAW:** 8개 출발 구역 무작위 배정.
- **TRAP_SETUP:** 팀별 덫 13개 비밀 설치, 각 팀 확정.
- **READY:** 전체 설치 완료 후 교사 게임 시작 대기.
- **RUNNING:** 서버 타이머 기동, 라운드 반복.
- **TIME_EXPIRED_SETTLING:** 00:00, 이미 시작된 문제 라운드만 마무리, 새 입력 금지.
- **FINISHED:** 결과 고정. 수동 종료면 바로 진입.
- **REVIEW:** 교사 주도 문제 복습과 전체 덫·이동 기록 공개 옵션.

### 11.2 라운드 단계

1. `MOVE_OPEN`: 학생이 주변 8방향 중 1칸 선택·확정. 속박 팀은 자동 정지. 교사는 팀 제출 상태를 확인.
2. `MOVES_LOCKED`: 교사가 진행(또는 선택한 자동 완료 정책), 서버가 이동 유효성 검사 및 일괄 위치 확정.
3. `ANIMATE_MOVE`: TV에 모든 동물 동시 이동·잔상 효과. 실제 판정은 서버가 담당.
4. `LANDING_SNAPSHOT`: 팀별 도착 셀의 전체 활성 덫 집합·개수 스냅샷, 방문 이력 확인.
5. `QUESTION_OPEN`: `n=0`이면 안전 보너스 또는 보상 구역 처리; `n>=1`이면 난이도별 1문제 제시.
6. `RESOLVE`: 정답/오답·타임아웃 채점, 덫 제거 병합·특수효과·오아시스/상대 시작 지점 보상·3×3 정찰 권한 부여.
7. `ROUND_SUMMARY`: TV 점수 갱신, 각 팀 처리 완료 표시, 교사 다음 라운드 버튼 대기. 남은 메인 시간이 0이면 `FINISHED`.

**중요:** 실제 상태 전이는 서버에서 단 한 번 이루어져야 한다. 교사의 중복 클릭, 학생의 중복 답안, 재접속, 이벤트 재전송, 타이머 만료가 겹쳐도 결과가 중복 적용되지 않도록 상태 버전·멱등성 키를 사용한다.

### 11.3 동시 이벤트 처리 순서 — 구현 기본안

`이동 잠금 → 위치 확정 → 덫 스냅샷 → 개인별 문제/안전 점수 → 정오답 채점 → 중복 없는 덫 제거 병합 → 오답 특수 효과 적용 → 보상 지급(오아시스 공동 순위 포함) → 정찰 권한 부여 → 점수 확정 → 종료 검사`

- 오아시스 공동 순위는 **해당 라운드 최초 도착 집합**을 일괄 처리한다. 답안 제출 속도로 순위가 달라지지 않는다.
- 귀환 등 특수 효과로 순간 이동한 출발 셀에서는 추가 덫·도착 보상 연쇄 판정을 하지 않는다.
- 시간 만료 중 이미 시작된 라운드 정산은 끝내지만 새 라운드를 열지 않는다.

## 12. 교사용 TV 화면 상세

- **보드 중심:** 16×16 모든 칸이 한눈에 보이게 최대한 크게 배치, 중앙 2×2 푸른 오아시스, 8개 출발 구역과 팀 동물 구별.
- **동물 표시:** 팀 고유 색·문자·동물 아이콘을 함께 표시(색약 사용자 배려), 이동 시 잔상·빛나는 위치·간단한 동선 애니메이션.
- **상태:** 라운드 번호, 남은 시간, 각 팀 현재 상태(이동 대기/확정/문제 풀이/제출 완료/속박/정찰), 점수 및 순위.
- **이벤트:** 덫 착지 시 경고/빛/사운드, 정답·오답 결과, 귀환·속박·혼란 아이콘, 오아시스 방문·보너스 축하 효과.
- **전체화면:** 클릭 한 번으로 전체화면 및 복귀. 브라우저 전체화면·사운드 정책과 호환.
- **중요한 비밀 유지:** 게임 중 타 팀 덫 위치, 정답, 팀별 정찰 선택 영역 상세는 공용 TV에 표시하지 않음. TV에는 이벤트 발생과 공개 점수만 표시.
- **결과 화면:** 우승 팀(공동 우승 가능), 전체 점수표, 획득 보너스·정답 수·이동 경로 요약. 교사가 요청하면 덫 전체 지도를 공개.

실제 DB 명칭과 마이그레이션은 코드베이스 조사 후 확정한다. 예시 엔터티:

- **이벤트 감사 로그:** 어떤 덫을 언제 밟고, 어떤 문항을 풀고, 왜 몇 점 변화했는지 교사가 확인 가능.

## 16. 서버 로직 의사코드

```text
function resolveLanding(team, cell, roundSnapshot):
    if team.didNotActuallyMove: return NO_ENTRY
    traps = roundSnapshot.activeTrapsAt(cell)  // 모든 팀, 일반+특수
    n = traps.length

    if n == 0:
        if isOrdinaryCell(cell) and not team.visitedCells.has(cell):
            award(team, +3, "SAFE_FIRST_VISIT")
        recordVisit(team, cell)
        return NO_QUIZ

    difficulty = n <= 2 ? EASY : n <= 4 ? MEDIUM : HARD
    q = chooseRandomQuestion(difficulty, excludingTeamHistoryFirst=true)
    assignQuiz(team, q, n, snapshotTrapIds=traps.ids)
    recordVisit(team, cell)

function settleAssignedQuiz(team, assignment, answer):
    require(validTeamAuth && !assignment.resolved && withinAllowedState)
    correct = serverGrade(assignment.questionId, answer)
    n = assignment.trapSnapshotCount
    if correct:
        award(team, +(n+2), "TRAP_CORRECT")
        markTrapSetForRemoval(assignment.snapshotTrapIds)
    else:
        award(team, -(n+1), "TRAP_WRONG")
        chooseAndApplySpecialEffectIfAny(assignment.snapshotTrapIds)
    markAssignmentResolvedExactlyOnce()

function settleRound(session):
    // 이동 이후 동일 칸 동시 착지 팀은 같은 덫 스냅샷 사용
    // 채점 결과를 집계하여 정답으로 제거될 덫을 중복 없이 제거
    applyAllPendingTrapRemovals()
    applySpecialEffectsWithNoRecursiveLanding()
    awardOpponentSpawnOncePerOpponentZone()
    newOasisArrivals = teamsEnteringOasisForFirstTimeThisRound()
    rank = 1 + numberOfTeamsThatArrivedInPreviousRounds()
    awardAll(newOasisArrivals, rank==1 ? 20 : rank==2 ? 30 : 15)
    markArrivals(rank); grantReconOnceToEach(newOasisArrivals)
    commitScoresAndEventsAtomically()
    if session.timerExpired: finishAfterSettling()
    else: enterRoundSummary()

function onTimerExpiry(session):
    disallowNewRoundAndNewMovement()
    if currentRoundHasAlreadyBeenLocked:
        transitionTo(TIME_EXPIRED_SETTLING)
        finishAfterCurrentRoundResolution()
    else:
        cancelUncommittedRound(); transitionTo(FINISHED)

function onTeacherForceFinish(session):
    verifyTeacherAndConfirm()
    blockAllSubmissionsImmediately()
    retainOnlyCommittedResults(); cancelUncommittedAssignments()
    transitionTo(FINISHED)

function rankTeams(teams):
    sortByScoreDescending()
    assignEqualRanksForEqualScores()  // 공동 우승 허용
```

**구현 주의:** 0덫 칸에서의 최초 방문 기록은 안전 점수의 중복 지급 방지 핵심이다. 정답 제출과 덫 소모를 해당 라운드 단위로 처리해 다른 팀의 문제 난이도가 답변 속도에 의해 달라지지 않도록 한다. 진행 중 입력의 실제 수락 마감 시각은 반드시 서버가 결정한다.

## 17. 게임 종료 후 수업 복습 모드

1. 종료 시 최종 순위·공동 우승·팀별 점수 표시.
2. 교사가 **문제 복습 시작** 버튼을 누르면 해당 게임에서 사용한 객관식 문제들을 목록으로 표시.
3. 교사가 문항을 선택하면 TV에 질문·선택지를 표시하고, **정답 공개** 버튼을 눌렀을 때 정답 및 해설 공개.
4. 난이도, 해당 문제를 푼 팀 수, 정답률, 오답 선택지 분포(개인정보 최소화)를 제공하면 좋다.
5. **전체 덫 지도 공개** 및 팀별 이동 경로 재생/조회 기능으로 전략을 비교하고, 학생이 선택 이유와 실패 원인을 발표할 수 있도록 한다.
6. 복습 모드에서 점수 수정은 금지. 결과 화면으로 되돌아가도 원래 최종 점수 유지.

## 20. 필수 테스트 체크리스트

### 보드·이동·설치
- [ ] 16×16=256칸, 중앙 2×2 오아시스, 8곳 2×2 출발 구역 좌표가 정확하다.
- [ ] 8방향 1칸 이동만 가능하며 경계 밖 이동/비정상 좌표가 서버에서 거부된다.
- [ ] 타 팀과 같은 칸에 동물·덫이 중첩 가능하다. 오아시스에는 덫 설치 불가.
- [ ] 팀당 일반 덫 10·특수 덫 3, 자기 덫도 발동, 자기 모바일에서 위치 반짝임.
- [ ] TV/다른 팀 응답에 숨겨진 덫 좌표가 포함되지 않는다.

### 점수·문제·덫
- [ ] n=0 일반 칸에서 팀별 첫 방문에만 +3; 재방문 0; 초기 출발 칸에서 자동 +3 없음.
- [ ] n=1,2 쉬움; n=3,4 중간; n>=5 어려움.
- [ ] **특수 덫만 1개**인 칸도 n=1로 쉬움 문제 출제 및 정오답 점수·효과 정상 처리.
- [ ] 일반 2개+특수 2개면 n=4 중간, 정답 +6/오답 -5.
- [ ] 정답이면 일반·특수 덫 전부 제거, 오답이면 모두 유지; 재방문 문제 재출제.
- [ ] 같은 칸 동시 착지 시 답안 제출 순서와 무관하게 동등한 n 스냅샷.
- [ ] 정답 처리 중복·점수 중복·동일 문항 답안 재전송이 방어된다.
- [ ] 주변 8칸 센서에는 자기/상대·일반/특수 덫 모두 합계 포함, 도착한 현재 칸 제외.

### 상태이상·오아시스
- [ ] 귀환 시작점 이동, 속박 다음 2라운드 정지, 혼란 다음 2라운드 센서 숨김.
- [ ] 오답 시에만 특수 효과 발동. 정답이면 제거, 오답이면 유지.
- [ ] 오아시스 최초 도착 +20/+30/+15, 팀당 최초 1회, 재방문 중복 없음.
- [ ] A·C 동시 최초 도착은 공동 1위 각 +20, 다음 B는 3위 +15.
- [ ] A 단독 최초, B·C 다음 라운드 동시 도착은 공동 2위 각 +30, 다음은 4위.
- [ ] 정찰 3×3 구역 1회 선택, 상대 덫 정보 해당 팀에만 공개하고 게임 종료까지 접근 가능.
- [ ] 상대 팀 출발 2×2 구역당 최초 1회 +10, 자신의 시작 구역은 보상 없음.

### 타이머·종료·복습
- [ ] 교사가 제한시간 설정(기본 15분), 일시정지/재개, 남은 시간 서버 기준 정확성 유지.
- [ ] **40점 획득해도 게임이 종료되지 않는다.**
- [ ] 00:00 시 새 라운드 차단, 이미 열린 문제는 정산 후 종료; 미진행 라운드 취소.
- [ ] 수동 종료 확인 후 즉시 입력 차단, 이미 확정된 점수로 결과를 계산.
- [ ] 점수 내림차순 우승, 동점 공동 순위·공동 우승 표시.
- [ ] 종료 후 교사 주도 전체 문제 복습/정답 공개, 덫 지도·경로 확인 가능.
- [ ] 기존 애니멀 더비 및 다른 `gamify_class` 게임의 메뉴·데이터·작동에 회귀 문제가 없다.

## 21. 구현 전에 남아 있는 세부 사항(기본안 적용 가능)

확정 규칙에 없는 부분을 Claude가 임의의 '합의된 사실'로 만들지 않도록 아래를 추적한다. 사용자가 추가로 정하지 않더라도 **개발은 기본안으로 진행 가능**하다.

| 주제 | 구현 기본안 | 이유 |
|---|---|---|
| 팀당 자기 덫 한 칸 중복 | 불허 | 13개 덫 분산·설치 조작 편의 |
| 자기 출발 2×2 덫 설치 | 불허 | 초반 불공정·자해 방지 |
| 동일 칸 동물 중첩 | 허용 | 동시 이동 충돌 간소화 |
| 특수 덫 복수 중첩 시 오답 | 가장 강한 효과 1개(귀환>속박>혼란) | 지나친 중첩 패널티 방지 |
| 오아시스·시작 구역에서 n=0 | 지역 고유 보상만, 일반 안전 +3 제외 | 특수 보상과 안전 보너스 이중 계산 방지 |
| 음수 점수 | 허용 | 벌점 공정성 |
| 문제 풀기 제한시간 | 별도 교사 설정, 기본 예시 60초 | 종료 후 무기한 대기 방지 |
| 팀별 문제 부족 | 중복 최소화 후 필요한 경우 재사용 | 수업 중 게임 중단 방지 |
| 타이머 만료 경계 | 이동이 잠긴 라운드는 정산, 잠기지 않은 라운드는 취소 | 결과 일관성 |
| 교사 수동 종료 중 미제출 문제 | 취소, 추가 점수·감점 없음 | 즉시 종료 요구 반영 |
| 오아시스 정찰 공개된 덫의 제거 | 제거 상태도 실시간 갱신 | 허위 위험 정보 방지 |
| 팀 수 | 기본 8팀 고정 | 현재 8개 시작 구역과 연동 |
