## 2. 무엇을 바꿨나

### 원본 저장소를 Cloudflare D1으로 (핵심)
- 학생·보고서·검토·전시·그룹 자료의 원본은 **D1(SQLite)**. 저장 한 건이 수 밀리초에 끝나고 줄을 서지 않습니다.
- **구글 시트는 교사용 사본으로 유지**: 5분마다(변경이 있을 때만) D1 → 시트로 전체 복사하고 한글 조회 탭도 다시 만듭니다. 교사 관리실의 **"한글 시트 새로고침"** 버튼은 즉시 복사합니다. 시트를 직접 고쳐도 사이트에 반영되지 않습니다(예전과 동일).
- 수행평가 규칙(`domain.js`)은 그대로이며, 저장 방식만 바뀌었습니다.
- 동시 저장 안전장치: 필요한 자료를 한 번에(일관된 시점으로) 읽고, 저장할 때 판단에 쓴 자료가 그사이 바뀌었으면 저장 묶음 전체를 취소하고 최신 상태로 다시 처리합니다. 같은 학생이 두 창에서 동시에 저장하면 한쪽만 저장되고 다른 쪽은 "다른 창에서 변경됨" 안내(덮어쓰기 없음). 동시에 '보고서 열기'를 여러 번 눌러도 보고서는 1개만 생깁니다.
- **시트 자료를 D1으로 옮기기(4-6) 전에는**: 전체 관리자 로그인만 가능하고 학생 접속은 "저장소를 옮기는 중" 안내, 시트 자동 복사도 멈춰 있습니다(빈 D1이 원본 시트를 덮어쓰지 않도록). 옮기기는 한 번에 전부 들어가거나 전혀 안 들어갑니다.
- 시트 복사는 D1 변경 번호(리비전)로 관리해서 빠지는 변경이 없고, 한 번에 하나만 실행되며(버튼과 자동 복사가 겹치면 "다른 시트 복사가 진행 중" 안내), 더 오래된 사본이 최신 사본을 덮지 못합니다. 원본 탭이든 한글 탭이든 실패하면 다음 실행(5분 뒤)에서 다시 시도합니다. 시트 한 칸 한도(48,000자)를 넘는 자료는 예전 시트 방식과 똑같이 저장 단계에서 거부되므로 사본이 손상되지 않습니다.
- **D1 연결(`wrangler.jsonc`의 `d1_databases` 블록)을 빼면 예전 Google Sheets 방식으로 그대로 동작**합니다(되돌리기용).

### 로그인·속도
- 로그인은 저장소 왕복 1회(처음 PIN 등록 때만 2회). 브라우저가 보낸 값은 허용 항목만 서버 내부로 전달.
- 로그인 횟수 제한은 Cloudflare Rate Limiting(IP 60초 300회, 학생별 60초 10회). 학교 공인 IP 공유를 고려한 값.
- 사진 권한 확인은 보고서 1건만 조회.
- 자동저장: 입력이 4초 멈추면 저장(계속 입력해도 최대 20초마다). 일시 오류만 5→10→20→40초(±30%)로 재시도.

### 첫 PIN 등록 단순화 (요청 사항)
- 로그인 화면의 **"처음 접속: PIN 등록" 버튼 삭제**. PIN이 없는 학생은 **일반 로그인 칸에 숫자 4자리를 넣으면 그 숫자가 PIN으로 등록**되고 바로 입장(입장 후 안내 메시지).
- 주의: 명단 정보(학년·반·번호·이름)를 아는 사람이 먼저 로그인하면 그 사람이 PIN을 정하게 됩니다(예전 버튼과 같은 성질). 첫 수업 때 본인이 직접 입력하도록 안내하세요. 잘못 등록되면 교사 관리실 → 학생 명단 → PIN 관리에서 재설정.

### 복사·붙여넣기 금지 (요청 사항)
- 서술형 답변 칸의 복사·붙여넣기·끌어놓기·우클릭 차단은 원래 운영 중이었음(운영 파일과 대조 확인).

### 4-6. 기존 시트 자료를 D1으로 옮기기 (1회, 4-5 직후 바로)
수행평가 전이라 보고서는 없지만, **학생 명단·연구 그룹·탐구 설정**은 옮겨야 합니다. 이 단계를 마쳐야 학생이 접속할 수 있고 시트 자동 복사가 시작됩니다.
0. 먼저 구글 시트 백업: 시트 메뉴 **파일 → 사본 만들기**(이름에 날짜). 옮기기 후 자동 복사가 원본 탭들을 D1 내용으로 덮어쓰기 때문입니다.
1. 사이트 → 교사 관리실 → **전체 관리자 비밀번호**로 로그인.
2. 같은 탭에서 브라우저 개발자 도구(F12) → Console에 아래를 붙여넣고 Enter:
   ```js
   fetch('/api/lab/rpc',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({action:'migrate.fromSheets',payload:{}})}).then(r=>r.json()).then(console.log)
   ```
3. 결과 `imported`의 숫자(Students 등)가 시트의 행 수(머리글 제외, Settings는 `rate:` 행 제외)와 맞는지 확인.
   - 오류가 나면 아무것도 들어가지 않은 상태(전부 아니면 전무)이므로 원인을 보고하고 그대로 다시 실행하면 됩니다.
   - "이미 옮겼습니다"가 나오면 완료된 것. `payload:{force:true}`는 **D1 전체를 시트 내용으로 교체**하므로, 옮긴 뒤 학생이 작성한 내용이 있으면 쓰지 마세요.
   - 시트에 자료가 없어도 한 번은 실행해야 합니다(빈 상태로 '준비 완료' 표시 + 효소 탐구 자동 생성).
4. 교사 관리실 → 학생 명단·그룹·탐구 활동이 보이는지 확인.
5. **"한글 시트 새로고침"** 버튼 → 구글 시트 한글 탭 '최근 갱신' 시각이 바뀌는지 확인. 실패하면 화면 안내 문구와 `wrangler tail`의 `sheets-sync failed` 로그를 보고.

2. **실제 휴대폰(iOS·안드로이드)** 에서 답변 칸에 한글 직접 입력·지우기·실행취소 정상, 붙여넣기 차단.
3. 여러 기기(가능하면 10대 이상)로 동시에 로그인·작성.
4. 5~10분 뒤 구글 시트에 방금 작성한 내용이 복사됐는지 확인(자동 복사).
5. 수업 중 모니터링: `npx wrangler tail --config wrangler.jsonc` (오류·`sheets-sync` 로그 확인).
